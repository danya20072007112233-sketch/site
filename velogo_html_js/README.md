# VeloGo Voronezh — HTML/CSS/JavaScript

Статический сайт аренды самокатов. Python и C++ для запуска не нужны.

## Быстрый просмотр
Открой `index.html` в браузере. Для карты и корректной работы модулей удобнее запустить локальный статический сервер (например, VS Code Live Server).

## Режимы
- **Демо без настройки:** использует localStorage браузера. Регистрация, бронирование, старт/завершение поездки работают на одном устройстве/браузере. Данные не синхронизируются с iPhone или другими устройствами.
- **Облачный режим:** подключи Supabase, чтобы аккаунт и данные хранились онлайн. В `config.js` укажи URL и anon/publishable key проекта. Выполни `supabase-schema.sql` в SQL Editor.

## Настройка Supabase
1. Создай проект на https://supabase.com/.
2. В панели проекта открой SQL Editor → New query, вставь содержимое `supabase-schema.sql` и нажми Run.
3. Открой Project Settings → API (или Data API / API Keys, в зависимости от интерфейса).
4. Скопируй Project URL и anon/public key (или publishable key).
5. Вставь их в `config.js`:
   `SUPABASE_URL: "https://....supabase.co"`
   `SUPABASE_ANON_KEY: "твой публичный ключ"`
6. Никогда не вставляй `service_role` / secret key в браузерный код.
7. В Authentication → URL Configuration укажи адрес опубликованного сайта как Site URL. Добавь его в Redirect URLs, если потребуется.
8. Для удобного тестирования можно отключить подтверждение email в Authentication → Providers → Email; для реального проекта лучше оставить подтверждение включённым.

## Публикация на GitHub Pages
1. Создай репозиторий GitHub.
2. Загрузи в корень репозитория `index.html`, `style.css`, `app.js`, `config.js`, `supabase-schema.sql`, `README.md`.
3. В репозитории открой Settings → Pages.
4. В Build and deployment выбери Deploy from a branch; Branch: `main`, folder: `/ (root)`, Save.
5. Через некоторое время GitHub Pages покажет публичную ссылку.

## Важно
Это учебный прототип, не сервис реальной аренды. Координаты самокатов демонстрационные; нет подключения к GPS/замкам, QR, эквайрингу или реальным платежам. Перед реальным использованием нужно усилить серверные правила бронирования, атомарно блокировать самокат и добавить админ-роли. В текущем облачном прототипе базовые политики защищают пользовательские записи, но не реализуют полноценную конкурентную блокировку самокатов.
